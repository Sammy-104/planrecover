# Submission narrative and recording script

## Product narrative

PlanRecover connects shared planning with understandable financial obligations. When a booking fails or a participant leaves, it shows what can be retained, which commitments need review, what refund is actually verified, and what cash is required for the next step.

People approve exact saved terms. The assistant prepares options using validated tools; it cannot authorize money movement. The ledger separates personal cost, actual contribution, friend balances, merchant payments and pending refunds. A receipt reconciles the planned purchase rather than adding a second estimate to the total.

The current demonstration uses a fictional merchant, CAD PayPal sandbox and a simulated Alexa+ client. Supplier data, seeded history, manual evidence and genuine provider results are labelled separately. Actual backend: React/TypeScript, Vinext/Vite Worker, D1/R2, trusted Site identity, PayPal REST adapters and an optional Canadian Bedrock profile.

## Recording script — target 2 minutes45 seconds

| Time | Screen and narration |
|---|---|
| 0:00–0:20 | Introduce a shared plan and the problem: changing plans should not hide who owes what. |
| 0:20–0:45 | Show participants, exact approval terms, private budget and confirmed prerequisites. |
| 0:45–1:10 | Reconcile a synthetic restaurant receipt to a planned meal; show cost versus contribution and one correct projected total. |
| 1:10–1:55 | Trigger a labelled disruption, compare keep/cancel/replace, explain retained cost and new cash independent of expected refunds. Show exact refund review and saved progress after reload. |
| 1:55–2:20 | Show an independently recorded genuine sandbox result if available; otherwise keep the fixture label visible and state the provider verification limit. |
| 2:20–2:40 | Show the assistant's reviewable preview and reminder inbox. Label model versus fallback behavior accurately. |
| 2:40–2:45 | State the product outcome and where to find the runnable source/walkthrough. |

## Release checklist

- Verify current organizer rules, deadline, track and source/access requirements against official current pages. Historical blueprint dates are not a fresh rules check.
- Choose judge access deliberately; current hosting/source are private.
- Attach current test/typecheck/build evidence and exact source revision.
- Record the final video from the actual current UI. This script is not a finished video.
- Include `LICENSE` and retained third-party runtime/asset notices.
- Keep unresolved provider verification explicit. A connected label, fixture payment or local screenshot does not prove live integration.
