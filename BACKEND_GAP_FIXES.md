# Eight backend gap fixes — October 15, 2026

This release implements the eight code gaps identified in the project-wide `BACKEND_GAP_AUDIT.md`, starting from Site version 15 (`fd8853361076b2226c468e9fcd5ab0ad1e31508a`). It preserves the existing CAD sandbox, private identity boundary, explicit financial approvals and immutable accounting. External activation and genuine provider journeys remain separate verification work.

## Implemented behavior

| --- | --- |

Reloading or background checks resumes progress. The CAD105 required now versus CAD100 available case fails affordability. Other members must review their own private constraints; expected refunds cannot pay for replacements. Unverified drafts remain saveable with warnings. |

A supplier cancellation changes booking state; only the approved recovery path changes the financial obligation.

## Invoice provider boundary

PayPal's invoicing refund-record endpoint records an offline refund; it does not transfer money. Consequently this release uses an explicit merchant-account handoff for invoice refunds and verifies the resulting invoice transactions. It never sends an invoice payment ID to the checkout capture-refund endpoint and never fabricates a refund from a button click. See the [official invoicing reference](https://developer.paypal.com/invoicing/reference/) and [invoice definition](https://developer.paypal.com/api/invoicing/v2/definitions/invoice/).

A part-paid invoice's old collection balance is resolved by an approved merchant edit: total equals already collected gross payments, due balance is zero, partial payments are disabled, and recipient/reference/description are retained. `invoice_collection_closures` preserves original terms. Until canonical evidence matches, departure remains blocked. The retained deposit is neither a new payment nor an invented write-off.

## Database and verification

`db/migration-schema.ts` provides the complete declarative migration model for all 48 application tables; `drizzle.config.ts` uses it. Generated migration `0017_connected_workflows.sql` adds seven tables, indexes/triggers and two nullable lifecycle/source columns. It does not rebuild or drop an existing table. The old invoice/reminder enum constraints remain compatible. Existing runtime schema exports are preserved.

Validation includes 49 regression suites, full TypeScript checking and the supported Worker build. New/extended real-SQLite tests cover durable workflow reconstruction, supplier identity and read-only uncertain-operation recovery, private affordability, deposit/remainder collection, invoice refund idempotency, invoice-funded recovery, tool-result persistence failures, reminder revocation, checkout/cancellation races and authenticated strict-input HTTP routes. A populated pre-release database migration rehearsal preserves plans, partial invoices and private conversation history, with foreign-key/integrity checks. Provider calls in regression tests are disabled and replaced by explicit fixtures.

Browser and deployment evidence, exact published source and GitHub mirror state are recorded in the project release status after publication. Passing fixtures establish the code paths; they do not establish external delivery or a live multi-person financial journey.

## Still requires external setup or operational verification

- The chosen supplier and email/push provider accounts, protocol-specific bridge where needed, credentials and genuine booking/delivery tests. User preference remains configurable adapters first.
- Bedrock access/quota resolution and a bounded hosted inference check under the existing zero-spend/Free-plan rules. This release makes no live AWS inference calls.
- Authorized public relay deployment/registration, private `PAYPAL_WEBHOOK_ID`, and genuine signed delivery. The relay remains local-only under the user's earlier instruction. Canonical polling remains available.
- Resume and verify the existing hourly Site schedule through supported controls; do not create a duplicate. A manual runner is not proof of an unattended tick.
- Real sandbox invoice deposit/balance/refund, multiple signed-in participants and complete supplier recovery journeys; hosted database/object restore and operator alerting drills.
- GitHub is a source mirror. GitHub Pages cannot run this Worker backend. Backend-capable hosting still needs trusted identity, actual database/object bindings, secrets, callbacks, jobs and a reviewed migration of user data.

Optional Amazon Location/Textract/Step Functions activation and a physical Alexa+ connection are outside these eight code gaps. The existing Step Functions example remains an approval handoff; the implemented durable recovery state machine runs in the application database.
